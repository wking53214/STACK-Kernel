# Changelog

## Unreleased

### Naming

In prose and comments the kernel is written ≡TACK. Crate, binary, file, metric, span and environment-variable names use `stack` or `STACK`. The repository is named STACK-Kernel.

### Renamed (breaking for anything outside this repository)

Anything that reads these names from outside the repository needs the new spelling. That includes dashboards, alert rules, scripts and CI.

| Kind | Old | New |
|---|---|---|
| Crates | `tack-*` (for example `tack-sentinel`) | `stack-*` |
| Binary | `tack-sentinel-verify` | `stack-sentinel-verify` |
| Prometheus metrics | `tack_*` (for example `tack_sentinel_trips_total`) | `stack_*` |
| Alert names | `Tack*` (for example `TackSentinelTamperEvidence`) | `Stack*` |
| Tracing spans | `tack.*` (for example `tack.greenwave.admit`) | `stack.*` |
| Environment variables | `TACK_ADAPTIVE_*`, `TACK_VERIFY_*`, `TACK_ANC_PIPELINE_*`, `TACK_SENTINEL_REDTEAM_CHILD` | the same names with the prefix `STACK_` |
| C++ CMake project and targets | `tack_containment_stack`, `tack_containment`, `tack_tests`, `tack_production_hardened` | `stack_containment`, `stack_containment`, `stack_tests`, `stack_production_hardened` |
| C++ ctest names | `TACKTests`, `TACKProductionHardened` | `STACKTests`, `STACKProductionHardened` |

Not renamed, on purpose:

- The key bytes `tack-sentinel-other-test-fixture-key-not-a-real-secret` and the files under `crates/stack-sentinel/tests/fixtures/`. The recorded Python signatures and fingerprints depend on them.
- The recorded runs in `manual/measurements/` and the review records in `manual/review/`.

### Added

- `stack-anc-ceiling` example `padding_jitter` and `manual/measurements/randomized_padding_2026-10-29.md`: a measurement-only experiment on whether random padding hides a timing leak. No shipped ANC behaviour changed. Fixed, random-replace and random-add padding in Sleep, Spin and Hybrid, with a negative control (identical inputs) and three known-size positive controls, over 15 separate launches (7.6 million timings) plus a supplementary run with finer random steps. Findings: a fixed ceiling hides the token check's timing difference to within 6 ns (Spin) and 1.5 ns (Hybrid) at about 60,000 samples per class; fine-grained random delay raises the samples an attacker needs by a large factor but never removes the leak; 8 coarse random steps leak through the shape of the noise; a predictable draw cancels the protection. The write-up recommends an opt-in option, not a default, and records that the earlier Spin 4.42 reading was not reproduced.
- `manual/sections/trident_puzzles.md`: design note for the Trident puzzle gate, which holds every piece of a declared puzzle until the whole is present and has passed inspection, so a hostile payload cut into harmless pieces is inspected where it is assembled. Defaults come from a synthetic simulation; the note lists what that simulation could not show.
- `stack-trident` `puzzle` (prototype, not wired into anything): `PuzzleConfig` with documented defaults and hard ceilings, and the strict piece format. A piece is a verified envelope whose payload has exactly the keys `kind`, `puzzle`, `index`, `total`, `root` and `data`; an abort has exactly `kind` and `puzzle`. Extra keys, upper-case or odd-length hex, text or float numbers and out-of-range values are refused. `root_of` commits to the finished puzzle with a domain-separated SHA-256 over the piece digests; `split` is the producer side.
- `stack-trident` `puzzle`: the `Inspector` trait, `InspectInput` (the assembled whole plus the trailing bytes of the sender's last released wholes) and `Finding` (`Pass`, `Suspicious`, `Hostile`). There is no default inspector. `DenyListInspector` is a reference tripwire for known byte patterns, including a pattern split across a join; it misses any paraphrase.
- `stack-trident` `puzzle`: `PuzzleGate`, which owns an `Arc<Trident>` and verifies every piece through it before touching any state. It holds pieces until a puzzle is complete, recomputes the root, inspects the whole with look-back over the tails of the sender's last released wholes, and only then releases. Incomplete puzzles explode after an idle limit (capped by a hard lifetime) and the sender takes a breach; an authenticated abort is free; over-limit senders get a "busy" refusal with no breach; a full holding area evicts the oldest incomplete puzzle; released roots are remembered for a replay window; a breaker allows a free allowance of breaches, then quarantines the sender for a limited time. A `Suspicious` finding is never a breach. State is in memory and inspection runs under the gate lock.
- `stack-trident` tests: `tests/puzzle.rs` (one test per rule) and `tests/puzzle_redteam.rs` (a hoarder, a marker cut over four puzzles, a flooder beside an honest sender, and a deterministic mixed run in which no hostile whole is released and no honest sender is quarantined).
- Docs: a puzzle gate section in the `stack-trident` crate docs and a pointer from `manual/sections/trident.md`, including the note that inspection runs under the gate lock.
- `stack-trident` `puzzle`: `RuleInspector`, the first real inspector. It normalizes before matching (case, spacing, zero-width, bidirectional and control characters), matches the operator's deny patterns (optionally through spacing), injection and prompt-leak phrases ported from GSA's tightened `BaselinePolicy`, and one narrow harmful-build rule, and looks back over the tails of earlier wholes. Shape problems (not UTF-8, NUL bytes, too many control characters, an oversize whole) are `Suspicious`, never `Hostile`. Measured on dev, held-out, red-team, paraphrase, encoding and benign sets; the paraphrase and encoding gaps are asserted in the tests. The gate still has no default inspector.
- `stack-trident` `puzzle`: metrics and spans for the gate with closed labels (`puzzle::telemetry`): messages by outcome, refusals and closes by reason, breaches, quarantine trips, open puzzles, held bytes and inspection time by finding. Nothing a sender, puzzle or inspector says becomes a label.
- Docs: the puzzle design note records the owner's decisions on its open questions (rules inspector first; quarantine stays separate; no persistence for now; no sequence relaxation; metrics built; the busy reply deferred until the gate is wired in; release timing parked), the rules inspector's measured results and cost, and the metric table with example alert rules.

### Changed

- `stack-trident` (breaking for any receiver that built a config with no audience): an audience is now required. `TridentConfig::validate`, and so `Trident::new`, refuses an empty `audience` (field `audience`) unless the new `allow_unbound_audience` is set, and `TridentConfig::unbound_audience()` is the named way to ask for that. The no-audience warning stays for the explicit opt-out. Set `audience` to this receiver's identifier. Closes the open question on binding the audience by default.
- `stack-trident` tests: 29 setups that built `TridentConfig::default()` now call `TridentConfig::unbound_audience()`; setups that already set an audience are unchanged. Three tests in `config.rs` asserted the old default and were updated to the new one: `default_is_valid` (now `default_with_an_audience_is_valid`, with the old default asserted refused in a new test), `default_config_warns_once_per_replay_assumption` and `bound_audience_and_restored_high_water_do_not_warn` (the epoch-off half). New tests cover the refusal, the opt-out and its warning, an over-long audience under the opt-out, and `Trident::new` refusing an empty audience.
- `stack-trident` (breaking for any producer of envelopes): `subject_digest` is now the CNS digest (`cns.gate.subject_digest`) of the payload, not the SHA-256 of its canonical JSON. This makes the CNS rendering the one binding-digest format across Enforcer, GSA, CCC, CCCb, DIT, the Sentinel witness and the Trident. The envelope version stays 1 because the Trident has no deployed producers. A new `cns_digest` module holds the port, and tests/cns_digest.rs checks it against the shared CNS digest vectors. The MAC, the strict parser and the canonical JSON are unchanged. Floats and integers beyond 2^53 - 1 are still refused. Closes the open question on a shared digest format.
- `stack-anc-adaptive`: `Trip::OperationPanicked` now resolves to `Resolution::Reject`, and the `Resolution::Quarantine` variant is removed from that crate. The pad has no sender identity and isolates nothing, so the old label described an action it did not take.
- `cpp` (`stack_host_binding.hpp`): the seccomp allowlist now carries an aarch64 syscall table beside the x86_64 one, and a `static_assert` holds each entry to the libc `__NR_*` value. On aarch64 the old x86_64 numbers allowed io_setup, io_destroy, quotactl, munlockall, flistxattr, mlock and accept while read, write, exit, exit_group, rt_sigaction, clock_gettime and futex got ENOSYS.
- `cpp` (`stack_host_binding.hpp`): `GovernedMinotaurHost::SetActiveCapabilities` now checks the in-flight counter under `capability_lock_`, and `ExecuteGovernedTransaction` raises that counter inside the same locked block as its capability snapshot. A capability change can no longer be applied between an unlocked counter read and the write while a transaction is starting.
- `stack-trident`: `TridentConfig::validate` now emits a `tracing::warn!` when `audience` is empty (any holder of the shared key can replay the envelope to any receiver) and another when `enforce_startup_epoch` is on with `restored_high_water_ms` at 0 (the restart replay guard then trusts the wall clock). Defaults and the result of `validate` are unchanged, so the default config warns twice.
- CI: a `workspace` job runs `cargo test --workspace --locked` for every crate outside the four ANC crates, which keep their own jobs. No clippy gate yet (findings remain) and no C++ job (Catch2 is not on the runner).
- `stack-trident`: `SenderState::is_idle` in `state.rs` uses `Option::is_none_or` in place of `map_or(true, ..)` (clippy `unnecessary_map_or`). Same result for every input.
- `stack-greenwave`: `Timing::is_epoch_boundary` uses `u64::is_multiple_of` in place of `t % epoch_len == 0` (clippy `manual_is_multiple_of`). `epoch_len` is always at least 1000, so the two forms agree.
- `stack-p3-2`: six clippy findings cleared with no behaviour change. `HardPreemptionKernel` drops its `config` field, which was stored by `new` after `validate()` and never read. `parse_limit` uses `Range::contains` and `GovernedLimits::effective` uses `Option::is_some_and`, each equal to the expression it replaces. `check_preemption_boundary` keeps its public `Result<(), TrapEvent>` return type and carries a targeted `#[allow(clippy::result_large_err)]` with a reason comment, because boxing the error would change a public signature. The `governed_workload` example uses `u64::is_multiple_of` in `is_canary_task`; its only caller passes a divisor above zero.
- `stack-minotaur`: three `seed % N == 0` tests in `tests/redteam.rs` use `u64::is_multiple_of` (clippy `manual_is_multiple_of`). The divisors are the literals 11, 97 and 5, so the results are identical and no assertion changed.
- `stack-transmission`: `Mode::for_epoch` in the shared test support (`tests/common/mod.rs`) uses `u64::is_multiple_of(2)` in place of `tag % 2 == 0` (clippy `manual_is_multiple_of`, reported once per test binary that includes the module). The divisor is the literal 2, so the fixture is unchanged and no assertion changed.
- CI: the `workspace` job now runs `cargo clippy --workspace --all-targets --locked -- -D warnings` before its tests and installs the `clippy` component. It covers every crate including the four ANC crates. The toolchain is pinned to Rust 1.99.0 so a new release cannot fail this step without a change here; move the pin deliberately, together with any new lint fixes. This replaces the "No clippy gate yet" note in the workspace-job entry above.
- Workspace `rust-version` is now 1.95 (was 1.94), so `AtomicU64::try_update` and `AtomicUsize::try_update` can replace the deprecated `fetch_update` in `stack-trident` (`clock.rs`) and `stack-anc-pipeline` (`gate.rs`); the two are the same operation under a new name. `stack-trident` `decode_hex_lower` uses `as_chunks::<2>()` in place of `chunks_exact(2)` (clippy `chunks_exact_to_as_chunks`); the length is checked to be exactly `2 * N` first, so no remainder exists. The whole workspace compiles on 1.95 and clippy is clean on 1.99.0. The README states the new minimum.
- `cpp` (`stack_host_binding.hpp`): the seccomp allowlist now includes `timer_settime` (x86_64 223, aarch64 110, each held to `__NR_timer_settime` by a `static_assert`). Before this, a sealed thread got ENOSYS when `HardenedPosixPreemptionGuard::Arm()` armed its deadline timer, so `ExecuteGovernedTransaction` could not succeed on any thread that had installed the filter.
- `cpp` (`stack_host_binding.hpp`, `ffi_wrapper.cpp`): every thread that calls `InitializeAndSeal` or `ExecuteGovernedTransaction` now installs its own seccomp filter, once, after creating its deadline timer. Before this the sealed state was one flag per host (and one process-global flag in the FFI), so only the first thread was filtered and every later thread ran unfiltered. The filter is not applied process wide with `SECCOMP_FILTER_FLAG_TSYNC`: that reaches threads that never called in and still leaves them unable to run a transaction, because `timer_create` is not allowlisted. A failed install leaves the thread unsealed and returns an error, as before.
- C++ test `test_defect2_concurrent_mutation` (`cpp/tests/layer4_redteam.cpp`, "Capability Mutation Race") no longer depends on scheduling. It failed 30 of 100 launches (28 with the setter never getting in, 2 with the mask left at `0xAA`). The capability code was not at fault: `SetActiveCapabilities()` correctly refuses a change while a transaction is in flight. The test now warms up each executor first, retries each change until it is applied, and checks that the last write landed. Both original assertions stay. 0 failures in 500 launches. A new deterministic test checks the in-flight rule itself, and a mutation check shows it catches a removed guard (the old test did not). Measurements and cause in `manual/measurements/cpp_capability_mutation_race_2026-10-29.md`. No ThreadSanitizer result: the seccomp filter blocks the sanitizer's system calls.
- `stack-ffi` (breaking for any caller of the changed function): `stack_host_set_capabilities` returns an `int` instead of `void`: 0 applied, -1 host not initialized, -2 refused because a transaction is in flight. The Rust `host_set_capabilities` returns `Result<(), CapabilityError>` (`NotInitialized`, `TransactionInFlight`) instead of `()`. This clears the compiler warning for the ignored `[[nodiscard]]` result of `SetActiveCapabilities()`. One existing test, `test_capability_setting`, now ignores the `Result` explicitly. The FFI's governor parameters, which make every FFI transaction return `RateLimitExceeded`, are unchanged.
